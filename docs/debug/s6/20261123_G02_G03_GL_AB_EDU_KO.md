# S6 G02/G03 — WSLg 렌더러·Qt 단독 진단기 (교육용 디버깅 보고서)

## 문제 정의 및 원인 가설
- 원본 G01의 첫 오류는 Gazebo GUI의 Failed to create OpenGL context. GLXINFO에서 D3D12 NVIDIA accelerated=yes라는 사실만으로 Qt/OGRE가 생성할 컨텍스트를 증명하지 못했습니다.
- 가설 A: Qt의 Wayland 백엔드가 OGRE와 충돌한다. 가설 B: D3D12 NVIDIA 선택을 Qt GUI에 일괄 적용한 부작용. 가설 C: llvmpipe CPU 렌더링 경로에서 문제가 재현되는지 별도 확인이 필요합니다.

## 최소 비교 설계
| 실험 | 기준 대비 변경 | 판정 제한 |
|---|---|---|
| baseline | 기존 환경 상속 | 현재 상태 재현 |
| xcb | QT_QPA_PLATFORM=xcb만 변경 | Wayland/Qt 영향 분리 |
| xcb_no_wayland | xcb 대비 WAYLAND_DISPLAY 제거 | XWayland 차이 분리 |
| xcb_nvidia_d3d12 | xcb 대비 명시 D3D12 NVIDIA 선택 | GPU 경로 비교 |
| xcb_llvmpipe | xcb에서 소프트웨어 렌더링 사용 | GPU 특이성 분리 |

## 구현 및 안전
- scripts/s6_wslg_gl_probe.py: os.environ.copy()로 분리된 프로세스별 환경, 고유 GZ_PARTITION, Gazebo GUI만 짧게 시험, 시작한 PID 프로세스 그룹만 SIGINT/TERM/KILL. pkill이나 글로벌 환경 변경 없음.
- 실제 Gazebo 출력과 glxinfo 결과를 원본 로그/JSON/작은 ZIP으로 보존합니다. OpenGL 오류, abort, 정상 종료, 일정 시간 생존을 분리합니다.
- **시간 동안 창이 살아 있어도 OpenGL/Gazebo/로봇 GUI PASS라고 주장하지 않습니다.** 실제 렌더링 영상·육안 검수는 별도입니다.
- ROS 2·Nav2·Goal을 단 한 번도 호출하지 않는 진단기입니다. GUI 자체가 센서 데이터 배달·복귀를 확인하는 실험이 아님을 분명히 합니다.

## 초심자 실습
1. launch/owner 로그의 Qt 메시지와 glxinfo 결과가 나타나는 다른 실행 계층을 그림으로 설명해 보십시오.
2. 실행: python3 scripts/s6_wslg_gl_probe.py --out-dir ~/samsungaxi_gui_evidence/s6_gl_probe
3. gui_profiles.json을 열어 renderer, exit_before_timeout, classification을 비교해 보십시오.
4. xcb가 성공처럼 보여도 창이 실제 3D 장면을 그렸는지 확인 전에는 GUI PASS가 될 수 없는 이유를 토론하십시오.
