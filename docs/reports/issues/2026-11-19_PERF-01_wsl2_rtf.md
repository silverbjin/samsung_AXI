# PERF-01 — WSL2 Gazebo RTF 약 0.50~0.60

- 최초 보고: 2026-11-19 KST
- 상태: **OPEN — 원인 분리 중**, 개선 RTF 미검증
- 현장: Windows WSL2 Ubuntu 24.04 / ROS Jazzy / Gazebo Harmonic, Waffle Pi + LiDAR + RGB-D, 강사 제공 화면 및 로그
- 시작 증거: Gazebo 엔티티·로봇 렌더링 정상, `Entity creation successful`, 화면 RTF 61.95%

## 현상과 실패 경계
주행 Goal을 발행하지 않은 `world` 시연에서 Gazebo가 실행되지만 RTF가 50~60%. 카메라 중복 GPU 렌더, WSLg 어댑터 선택, WSL 메모리/CPU 제한, GUI 비용은 아직 가설. **정확한 기여도는 검증되지 않았으므로 원인 확정 금지.**

로그의 Ogre2 FSAA 지원 경고, QML binding loop, SDF 확장 `gz_frame_id`, visibility-mask 경고는 각각 경고로만 확인됨. 현재 월드·센서 실행을 중단시킨 최초 치명 오류가 아닙니다.

## 확인된 설계 문제와 조치
소스 조사로 공식 Waffle Pi의 기본 RGB 카메라(30Hz)와 신규 등록 RGB-D(5Hz)가 별도로 존재하는 것을 확인. 중복 센서 렌더링 비용을 줄이기 위해 생성 SDF 사본에서만 기본 RGB 제거. `/restaurant/rgbd/image`, Depth, PointCloud2와 `/scan`은 유지. lidar `visualize`만 비활성화. 생성된 SDF/CI에서 실제 센서 메시지 수신 검증을 요구함.

GPU 및 RAM은 환경별로 다르므로 `.wslconfig` 무조건 변경 또는 강제 NVIDIA 지정 금지. 읽기 전용 수집기 추가.

## 동종 환경 검증
정적 검증: 코드/계약 검사 통과. ROS/Gazebo 실제 L2 및 강사 WSL2 변경 후 RTF 재측정은 아직 미실행. 이 상태에서 **RESOLVED 또는 RTF 1.0 주장 금지**.

## 교육용 해설
RTF는 여러 원인이 결합된 시스템 현상. 경고 1개를 근본 원인으로 단정하거나 GPU가 존재한다는 사실을 GPU 활용 증거로 오인하지 않는다. 먼저 실제 렌더러와 메모리 여유를 읽고, 변경 범위를 중복 렌더링 1곳으로 제한한 뒤 같은 장면에서 비교한다.

Microsoft WSL config: https://learn.microsoft.com/en-us/windows/wsl/wsl-config
Microsoft WSLg GPU selection: https://github.com/microsoft/wslg/wiki/GPU-selection-in-WSLg
