# B-15 디버깅 01 — 증거 TAR 추가 후 과거 오류 계약과 충돌

## 재현된 RED

기존 `tests/test_b_a13_runner.py`는 잘못된 인수 경로를 전달했을 때 오류를 **stderr**에서 읽고 `ai/data/private` 자체가 존재하지 않는다고 단언했습니다. 첫 진단 구현은 stdout/stderr를 단일 `tee`로 병합해 오류 메시지를 stdout으로 바꾸고, 모든 시도의 아카이브 보존을 위해 `ai/data/private/b_a13_diagnostics`를 미리 생성했습니다. 로컬 테스트에서 5건이 FAIL했습니다.

## 원인

CI 검증 성공과 WSL2 진단 가능한 실행은 다른 계약입니다. **실패 자체가 발생한 경우에도 `execution.log`와 진단 TAR는 생성해야 하지만**, 실패한 인수에 `raw/`·`review/` 디렉터리가 만들어져서는 안 됩니다. 기존 stderr/stdout 경계와 종료 코드를 바꾸는 것 역시 인터페이스 회귀입니다.

## 최소 변경 및 GREEN

- 성공·실패의 출력은 FIFO 별도 전송으로 사용자 화면에 실시간 유지합니다. 기존 stderr 마커/종료 코드는 유지합니다.
- 양쪽 `tee`가 종료한 뒤 실행 로그를 병합하고 진단 아카이브를 봉인합니다.
- 기존 부정 테스트는 검증되지 않은 인수 `b_a13_review_*` 미생성을 검사하도록 정밀화하고, 진단 전용 폴더 생성은 허용합니다.
- 새 테스트에서는 원본 없음, 잘못된 SHA, 가져오기 단계 실패, 성공 결과의 HTML·PNG·SVG 묶음과 내부 SHA, 민감·추가 파일 누출 거부를 검사합니다.
- 로컬 결과: 기존 A13 포함 **41 PASS / 3 SKIP** (3 SKIP은 기존 B collector가 로컬 샘플 미러에 없기 때문). GitHub HEAD의 결과는 별도 원격 검증 필요.

## 주니어 교육 포인트

1. `exit 0`과 데이터 승인·C 학습 준비는 동일하지 않습니다.
2. 실패 로그도 PASS 로그만큼 보존돼야 재현 없이 최초 실패를 진단할 수 있습니다.
3. stderr를 stdout으로 합치는 변경은 사람 눈에는 같아 보여도 테스트·자동화 계약을 깹니다.
4. ZIP/TAR에 HTML만 넣으면 상대경로 이미지가 사라질 수 있습니다. 동일 상대경로의 자산과 SHA 목록을 함께 묶어야 합니다.
5. 운영자 승인 원장이나 원본 대용량 TAR를 습관적으로 아카이브에 넣어 공유하는 것은 보안·용량 위험입니다.
